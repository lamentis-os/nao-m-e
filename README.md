# NAO-M-E

[![CI](https://github.com/lamentis-os/nao-m-e/actions/workflows/ci.yml/badge.svg)](https://github.com/lamentis-os/nao-m-e/actions/workflows/ci.yml)

NAO-M-E is a deterministic, in-memory Rust kernel for symbolic episode memory.
It is a research mechanism rather than an LLM memory product.

## Overview

- Episode atoms are immutable and store a caller-owned provenance source ID.
- Activation uses deterministic integer fixed-point transitions.
- Sparse directed relevance controls how activation flows between atoms.
- Caller-supplied memory IDs namespace the atom IDs generated by each memory.

## Quick start

```rust
use std::error::Error;

use nao_m_e::{
    Activation, EpisodeDraft, MemoryId, MemoryV0, PredicateId, SourceId, Statement,
    TermId, TimestampMs,
};

fn main() -> Result<(), Box<dyn Error>> {
    let observation = Statement::new(
        PredicateId::new(1),
        vec![TermId::new(10), TermId::new(11)],
    )?;
    let memory_id = MemoryId::new(0x7b4f_6be0_32c2_4be8_96b8_7394_f734_85af)?;
    let mut memory = MemoryV0::new(memory_id);
    let atom = memory.insert_episode(EpisodeDraft {
        occurred_at: TimestampMs::new(1_000),
        recorded_at: TimestampMs::new(1_001),
        context: Vec::new(),
        observation,
        action: None,
        outcome: None,
        source: SourceId::new(7),
    })?;

    memory.stimulate(atom, Activation::ONE)?;
    assert_eq!(memory.top_k(1)[0].atom_id, atom);
    Ok(())
}
```

## Boundaries

The kernel performs no persistence, loading, synchronization, or multi-writer
coordination. Episode content is symbolic: it stores caller-owned numeric
identifiers rather than free text or embeddings, and it makes no LLM calls.
Relevance controls accessibility; it does not establish truth or confidence.

See the [V0 contract](docs/v0-contract.md) for the exact state, identity,
transition, graph, and recall semantics. Generate local API documentation with
`cargo doc --workspace --no-deps --all-features --locked --open`.
